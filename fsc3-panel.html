Two ways to connect.
1 · Local bridge (works in any browser, and over LAN) — run python fsc-bridge.py in this folder, open http://localhost:8765/, set Instrument target to serial://COM5 or tcp://<instrument-ip>:5025, press Connect.
2 · Web Serial (Chrome/Edge only, no helper process) — pick Web Serial as the transport and choose the port in the browser dialog. The browser, not this page, picks the port; ports the OS cannot open are hidden from that dialog.
If COM5 never appears in the Chrome dialog: that is a driver problem, not a browser one — Chrome hides ports the OS cannot open. Measured on this machine: the FSC3 enumerates as CDC class 02 / subclass 02 / protocol 0xFF (vendor-specific control protocol) with no Union functional descriptor, so Microsoft's generic usbser.sys binds to it but cannot drive it. CreateFile succeeds, then SetCommState and EscapeCommFunction(SETDTR) — the CDC SET_LINE_CODING and SET_CONTROL_LINE_STATE requests — both fail with ERROR_GEN_FAILURE (31). Bytes do reach the bulk OUT pipe, but the instrument never replies without that handshake, so serial://COM5?raw=1 (which skips line configuration) was tried and does not work on this device.
Fix: install the R&S USB driver (ships with R&S InstrumentView) and bind it to the device in Device Manager, replacing Microsoft's usbser. Then either transport works. Match Baud/terminator to Setup → Instrument Setup on the FSC.
